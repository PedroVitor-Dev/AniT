# Central de documentação

Esta documentação descreve o **AniT 1.0.1**, publicado para Windows x64. Quando houver divergência, o código e os testes da tag da versão são a fonte da verdade.

## Para quem usa

- [Instalação e atualização](INSTALLATION.md): download oficial, SHA-256, SmartScreen, atualização e desinstalação.
- [Manual de utilização](USER_GUIDE.md): perfis, biblioteca, busca, player, histórico, calendário e organização.
- [Referência de configurações](SETTINGS.md): todas as onze categorias e o efeito de cada opção.
- [Backup e migração](BACKUP_AND_MIGRATION.md): arquivo `.anitbackup`, restauração, segurança e religação dos vídeos em outro PC.
- [Solução de problemas](TROUBLESHOOTING.md): diagnóstico de instalação, PIN, scan, artes, player e backup.
- [Privacidade e dados locais](PRIVACY.md): arquivos criados, PIN, consultas externas e exclusão de dados.
- [Sistema de conquistas](ACHIEVEMENTS.md): catálogo, AniPoints e regras de desbloqueio.
- [Suporte](../SUPPORT.md): onde tirar dúvidas ou relatar problemas.

## Para quem contribui

- [Guia de contribuição](../CONTRIBUTING.md): issues, branches, commits, documentação e pull requests.
- [Ambiente de desenvolvimento](DEVELOPMENT.md): ferramentas, comandos, banco local e padrões técnicos.
- [Arquitetura](ARCHITECTURE.md): responsabilidades das camadas e fluxos principais.
- [Roadmap](ROADMAP.md): entregas atuais e direção futura.
- [Processo de release](RELEASING.md): versionamento, validação, instalador e publicação.
- [Changelog](../CHANGELOG.md): histórico das versões publicadas e alterações ainda não lançadas.
- [Avisos de terceiros](../THIRD_PARTY_NOTICES.md): dependências e componentes distribuídos.
- [Governança](../GOVERNANCE.md): papéis, decisões e manutenção.
- [Segurança](../SECURITY.md): comunicação responsável de vulnerabilidades.
- [Código de Conduta](../CODE_OF_CONDUCT.md): comportamento esperado na comunidade.

## Fonte da verdade

1. O código e os testes da versão definem o comportamento implementado.
2. `CHANGELOG.md` registra mudanças já publicadas.
3. O roadmap descreve intenção, não compromisso de entrega.
4. Uma mudança de fluxo público deve atualizar a documentação no mesmo pull request.

Encontrou uma inconsistência? Abra uma issue de documentação ou envie um pull request pequeno e direto.
